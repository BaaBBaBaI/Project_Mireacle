# Отчет по практическим работам №21, №22, №23   
**Дисциплина:** Фронтенд и бэкенд разработка   
**Выполнил:** студент группы ЭФБО-06-24 Веневцев Артем Андреевич   
## Введение   
Целью данного комплекса практических работ являлось создание отказоустойчивой, масштабируемой и оптимизированной серверной инфраструктуры. В ходе выполнения были последовательно внедрены технологии кэширования, балансировки сетевой нагрузки и контейнеризации микросервисов.   
 --- 
## 1. Практическая работа №21: Кэширование данных (Redis)   
**Цель:** Снижение нагрузки на базу данных и ускорение времени ответа сервера (Node.js/Express) за счет использования In-memory хранилища Redis.   
**Реализованный функционал:**   
- Интегрирована библиотека `redis` для кэширования результатов ресурсоемких запросов.   
- Настроена логика времени жизни кэша (TTL):   
    - Для маршрута `GET /api/users` кэш сохраняется на 1 минуту.   
    - Для маршрута `GET /api/products` кэш сохраняется на 10 минут.   
- Реализована инвалидация (сброс) кэша: при выполнении `POST`, `PUT` или `DELETE` запросов к сущностям, соответствующие ключи в Redis удаляются для предотвращения выдачи устаревших данных клиенту.   
 --- 
   
## 2. Практическая работа №22: Балансировка нагрузки   
**Цель:** Обеспечение распределения входящего трафика между несколькими экземплярами серверного приложения для повышения отказоустойчивости .   
**Реализованный функционал:**   
- Запущены два идентичных backend-сервера ( `backend-1`, `backend-2`) и один резервный ( `backend\_backup`).   
- **Основной балансировщик (Nginx):** Настроен на прослушивание порта 80. Трафик распределяется по алгоритму Round Robin . Добавлены параметры проверки жизнеспособности узлов (Health Checks) `max\_fails=2` и `fail\_timeout=30s`. При падении одного из серверов Nginx автоматически исключает его из пула.   
- **Альтернативный балансировщик (HAProxy):** Развернут на порту 8080 для демонстрации альтернативного программного решения. Настроена директива `check` для мониторинга доступности узлов.   
 --- 
   
## 3. Практическая работа №23: Контейнеризация с Docker   
**Цель:** Изоляция среды выполнения приложения и автоматизация развертывания инфраструктуры .   
**Реализованный функционал:**   
- Написан `Dockerfile` для упаковки Node.js приложения. Использован многослойный подход (копирование `package.json` до исходного кода) для оптимизации кэширования при сборке образа .   
- Создан конфигурационный файл `docker-compose.yml`, описывающий весь стек.   
- Все контейнеры (балансировщики, backend-узлы, база данных Redis) объединены во внутреннюю виртуальную сеть `app-network` (driver: bridge) .   
- Настроено проксирование Nginx с использованием внутренних DNS-имен Docker (например, `proxy\_pass http://backend`) вместо статических IP-адресов.
