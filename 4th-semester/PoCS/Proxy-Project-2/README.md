## 1. Цель работы
Изучить основные методики модульного и интеграционного тестирования программного обеспечения и применить их для верификации компонентов разрабатываемого HTTP-прокси-сервера.

## 2. Описание реализации
В качестве тестового фреймворка был выбран **GoogleTest (GTest)**. Сборка тестирующих программ изолирована в отдельную директорию `tests`, а логика управления кэшем вынесена в статическую библиотеку `proxy_core` для удобной линковки.

### Набор модульных тестов (Unit Tests)
Для класса `CacheManager` реализовано 12 тест-кейсов, покрывающих методы `put()` и `get()` при различных входных данных:
* Тестирование стандартной записи и чтения данных.
* Проверка обработки пустых строк в качестве контента или URL-адреса.
* Стабильность работы с большими объемами данных (обработка буфера размером 1 МБ).
* Корректность парсинга URL-адресов со специальными символами и параметрами запроса.
* Проверка логики перезаписи данных по уже существующему ключу.
* Обработка ситуации Cache Miss при отсутствии ресурса.

### Тестовые сценарии (Integration Scenarios)
Реализованы два комплексных сценария, имитирующих реальные этапы работы корпоративного прокси-сервера:
1. **Сценарий жизненного цикла GET-запроса:** последовательный переход от состояния отсутствия данных в кэше к их скачиванию, сохранению и мгновенному извлечению при повторном обращении (Cache Miss -> Put -> Cache Hit).
2. **Многопоточный стресс-тест:** эмуляция пула потоков исполнения (Thread Pool), осуществляющих параллельный конкурентный доступ к общему экземпляру `CacheManager` (Singleton) для проверки отсутствия состояний гонки.

```bash

cmake ..
cmake --build .
ctest --output-on-failure
```
